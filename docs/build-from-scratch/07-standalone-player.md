# 07 - Standalone Player (Vite + Cloudflare Pages)

## Meta

- Goal: stand up a separate Vite app that mirrors the shared player assets into `public/` and builds them for Cloudflare Pages.
- Verification: `cd player && npm install && task player:sync && npm run dev` boots the dev server on `http://localhost:5176/` and renders the replay UI.

## 7.1 Folder Layout

```
player/
├── package.json              own deps (vite, vitest, jsdom, sharp, etc.)
├── vite.config.ts            base path config + Drive proxy middleware
├── vitest.config.ts          jsdom + sharedTestConfig
├── tsconfig.json             strict, moduleResolution bundler
├── index.html                entry HTML
├── _redirects                Cloudflare Pages redirect rules
├── scripts/sync-player.js    mirrors shared theme/icons into public/
├── public/                   generated by sync-player.js
│   ├── player.css
│   ├── player.js
│   ├── theme.css
│   ├── theme-init.js
│   ├── icons/
│   └── vendor/
├── src/
│   ├── main.ts               boot
│   ├── drive-adapter.ts      Drive API fetcher for the standalone app
│   ├── extension-detector.ts distinguishes extension-loaded vs standalone
│   ├── zip-parser.ts         JSZip-based artifact parser
│   └── env.d.ts
└── functions/
    └── api/
        └── drive.js          Cloudflare Pages function (same proxy as middleware)
```

## 7.2 Initialise the Folder

```bash
mkdir -p player
cd player
npm init -y
npm install vite vitest jsdom @vitest/coverage-v8
```

Then copy the existing `package.json`, `vite.config.ts`, `vitest.config.ts`, `tsconfig.json` from a reference checkout (or write them per `7.3`).

## 7.3 `vite.config.ts`

The two non-default pieces are the fixed port `5176` and a `/api/drive` middleware:

```ts
import { defineConfig } from "vite";
import { gnTracingDriveProxy } from "./scripts/drive-proxy";

export default defineConfig(({ mode }) => ({
  base: mode === "production" ? "/player/" : "/",
  server: {
    port: 5176,
    strictPort: true,
    middlewareMode: false,
  },
  plugins: [
    {
      name: "gn-tracing-drive-proxy",
      configureServer(server) {
        server.middlewares.use("/api/drive", gnTracingDriveProxy);
      },
      configurePreviewServer(server) {
        server.middlewares.use("/api/drive", gnTracingDriveProxy);
      },
    },
  ],
}));
```

`gnTracingDriveProxy` does:

1. Reads `?id=<fileId>` from the URL.
2. Issues a fetch to `https://drive.usercontent.google.com/download?id=<id>`.
3. If Google returns a confirmation HTML page (rare for public files), parses the form and follows the confirmation POST.
4. Streams the bytes back to the browser.

The same logic exists as a Cloudflare Pages Function under `functions/api/drive.js` so production deployment behaves identically.

## 7.4 The `sync-player.js` Script

`scripts/sync-player.js` mirrors shared design-system assets into `player/public/`:

- `../shared/` — `theme.css`, `theme-init.js`
- `../icons/` — brand icons + Phosphor font (`icon.svg`, `icon32.png`, `phosphor-icons.css`, `Phosphor.woff2`)

The script refuses to run if the source folders are missing and prints what it copied. It is invoked by:

```bash
node scripts/sync-player.js          # or
task player:sync                     # from repo root, chapter 09
```

`task player:build` and `task player:dist` chain `player:sync` automatically before the Vite build.

## 7.5 `index.html` and the Entry

`index.html` mounts the replay UI. It links `theme.css`, `theme-init.js`, `player.css`, and loads `player.js`. Both `main.ts` (bootstrap) and any module imports are bundled into the player output because `index.html` references a single entry `<script type="module">`.

The application reads `?id=<fileId>` from the URL, asks the proxy for the zip bytes, calls `zip-parser.ts` to extract the artifacts, and dispatches rendering events that the (bundled) `player.js` consumes.

## 7.6 `_redirects` and Base Path

Cloudflare Pages reads `_redirects` for SPA-style fallbacks. The minimal file is:

```
/api/*  /api/:splat  200
/*      /index.html   200
```

`base: "/player/"` in production is consumed by the same player code that renders standalone or extension replay; the difference is the absolute URL generated by `buildExternalPlayerUrl(...)` in `src/shared/player-host.ts`.

## 7.7 Local Smoke Test

```bash
cd player
node scripts/sync-player.js
npm run dev
# open http://localhost:5176/?id=<driveFileId>
```

You should see the replay UI with the video player, console/network panels, source-map-resolved stack frames, and the storage/DOM tabs when the artifact contains them.

## 7.8 Deploy

`task player:deploy` runs `deploy.sh`, which:

1. Builds with `npm run build` (production mode, base `/player/`).
2. Uploads `dist/` to Cloudflare Pages via `wrangler pages deploy`.

Required environment:

- `CLOUDFLARE_API_TOKEN` — chapter `10`.
- `CLOUDFLARE_ACCOUNT_ID` — chapter `10`.
- `CLOUDFLARE_PAGES_PROJECT` — defaults to `gn-tracing-player`.

## 7.9 Notes

- The standalone player's `dev` port is fixed at `5176`. It matches `PLAYER_LOCAL_PORT` consumed by chapter `04` so the extension's "open in popup" link can land on the same origin during local testing.
- Vendored `luna-object-viewer` and `luna-json-editor` are kept in sync via the same `sync-player.js` step and never imported from a CDN.

## You Should Now Have

- A running Vite dev server at `http://localhost:5176/` that loads the replay UI.
- A working `gn-tracing-drive-proxy` middleware that returns zip bytes for a known Drive file id.
- A production build under `player/dist/` ready for `wrangler pages deploy`.
