## Current Snapshot

Docs describe the current architecture where GN Tracing records one Chromium tab, captures DevTools evidence in memory with profile-based capture controls, enriches console and initiator locations with sourcemaps, uploads the finished session as a Google Drive zip package, and opens a hosted replay at `https://tracing.gnas.dev/<zip-file-id>`.

Replay storage is package-scoped. Each upload writes one `gn-tracing-*.zip` directly into the configured upload folder. Unprotected zips contain compact `metadata.json`, `manifest.json`, `recording-index.json`, optional `report.json`, optional `events.json`, optional `screenshot.jpg`, optional log artifacts, and ordered `video.part-XXX.webm` files. JSON/text entries are DEFLATE-compressed when that reduces size, while video/image entries stay stored. Password-protected uploads keep that package shape but protect ZIP entry payloads with the configured password after any entry compression, so downloaded archives prompt for the password in compatible unzip tools and the player unlocks entries before loading artifacts. Legacy encrypted-payload packages remain readable in the player. The zip file ID is the public entrypoint for the player; direct-file query params remain only as a legacy parser path.

New replay packages can include `report.json`, `events.json`, `privacy.json`, `diagnostics.json`, and optional `screenshot.jpg` alongside the original metadata/log/video artifacts. `report.json` stores the generated report title, page URL/title, timestamps, duration, counts, and environment context after report metadata redaction. `events.json` stores ordered navigation/click/focus/submit summaries without raw typed input. `privacy.json` stores policy version, selected privacy profile, artifact flags, redaction counts, and known limitations without raw secret values. `diagnostics.json` stores redacted source-map load attempts and failure reasons without embedding full sourcemap content, while generated-only console/network frames can carry compact `sourceMapStatus` for resolver misses. `screenshot.jpg` is captured from the visible tab at stop time on a best-effort, size-limited path and is omitted when unavailable. The player renders a report summary, environment chips, event seek rows, timeline markers, privacy summary, source-map status messages, and optional screenshot while still loading old packages without those artifacts.

Recording privacy is client-side and policy-driven. Standard, strict, and custom privacy profiles control built-in redaction for sensitive headers, URL query params, JSON/form body fields, console values, WebSocket text payloads, report metadata, and event metadata. The injected content script receives only safe privacy settings for event sanitization and selector-based visual masking; plaintext ZIP passwords and Drive credentials remain in extension storage/service-worker upload paths. Selector-based masking is best-effort and records package limitations when selectors are invalid or injection is unavailable.

Console replay artifacts can include bounded source snippets derived from sourcemap `sourcesContent` at capture stop time. Inline maps are decoded directly and external maps are loaded best-effort through CDP protocol requests that avoid page-context `fetch(...)`. Error remote objects logged as console arguments can carry parsed V8 stack frames in `SerializedRemoteObject.stackTrace`; those frames are source-map resolved, compacted, redacted, and rendered separately from the raw Error message. The player renders resolved locations, snippets, and optional diagnostic status in console/network detail views without fetching original sourcemaps or application source files during replay. When source content is unavailable, replay falls back to the resolved source file, line, column, and stack labels; when no mapping result exists, frame-level status or diagnostics can explain missing maps, HTML/non-JSON map responses, HTTP failures, missing frame ids, or loaded maps without matching segments.

Replay downloads can use Google Drive API `files.get?alt=media` with the current in-memory OAuth token when the player runs in the extension context. Hosted standalone replay keeps `/api/drive` as the no-token fallback; that proxy resolves Google Drive's large-file confirmation pages, including form-based confirmation pages, before streaming artifact bytes to the browser. If Drive still returns HTML instead of a zip package or legacy JSON index, the proxy returns a non-cacheable error and the player removes stale cached HTML before retrying network downloads.

The popup and history surfaces expose start/stop/remove recording controls, auto-upload when connected, per-file upload progress, release update checks, GitHub/contribution links, and recent upload history stored only in local extension storage. Popup, Settings, and full History surfaces share the same dark glass-panel theme, rounded cards, and action-button treatment, with the full-page surfaces using a wider layout. A dedicated Settings page owns configurable Drive target folders, optional zip password settings, capture profiles, and advanced console/network/WebSocket capture controls. The Settings page supports English/Vietnamese UI text and per-field help dialogs written for QC/tester users. Upload settings can be recovered from the popup session snapshot when the durable local settings key is missing, then backfilled to local storage. Full debug capture is the default so new recordings capture all supported console, network, body, initiator, and WebSocket details; blank size-limit fields mean no byte limit. Lean/balanced/custom profiles let users reduce artifact detail before recording. Popup capture controls and the capture queue are hidden until Drive is connected. Production extension builds require explicit OAuth/extension identity, and Store package validation plus versioned release zip packaging run through `Taskfile.yml`.

Developer tooling uses Biome from the root package for repository formatting, linting, and import organization across supported source files. `Taskfile.yml` exposes `lint`, `format`, `format:check`, and `check` aliases over the root npm scripts. Husky installs a versioned pre-commit hook that runs `biome check --write --staged` with unknown-file tolerance and re-stages safe fixes for staged files, while generated dependency/output folders and bundled icon assets stay outside the Biome scan scope.
